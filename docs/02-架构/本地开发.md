# 本地开发

## 前置条件

- Windows、Python 3.10+、`uv`、Node.js、npm。
- Agent 模型环境变量，至少包括 `MODEL_ID` 和对应模型凭据；Agent 依赖由 `apps/agent-runtime/pyproject.toml` 与 `apps/agent-runtime/uv.lock` 独立维护。首次使用可从仓库根目录执行 `uv sync --project apps/agent-runtime`。
- RAG 依赖由 `apps/rag/pyproject.toml` 与 `apps/rag/uv.lock` 独立维护；Compose 构建仍读取 `apps/rag/requirements.txt`，无需把 RAG 依赖安装进 Agent 环境。
- RAG 若使用 Compose，需要 Docker Desktop；按 `apps/rag/.env.example` 与 `apps/rag/config` 的非敏感模板，以及 `data/rag` 的 active profile、数据根和密钥配置模型、数据库和密钥。
- 本项目当前没有把 RAG 服务打包进 Electron；desktop 启动前应确认 RAG 服务地址可用。

## 一次性准备


```powershell
Set-Location D:\A-xk-project\Buffeed（请改为自己的目录）

uv --version

uv sync --project apps/agent-runtime
```


运行已有 Python 测试（包含 RAG 集成测试依赖）：


若测试仍报告 MCP 配置数量断言，先保留完整失败输出；当前 bundled `local-rag` 配置会与临时测试配置合并，这属于测试 fixture 与默认配置语义的对齐问题，不影响下面的启动调试流程。

## 启动顺序

建议使用三个 PowerShell 终端。以下命令均从仓库根目录开始。

### 终端一：Agent API

```powershell
Set-Location D:\A-xk-project\Buffeed（请改为自己的目录）
uv run --project apps/agent-runtime python apps/agent-runtime/run.py
```

Team runtime 和 durable journal 会被加载，当前回合可使用 Team 写工具；回合结束或下一回合开始时，旧成员会被协作式挂起。可用以下命令确认实际工具池：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health | Format-List status,team_tools_enabled,team_tools
```

### 终端二：RAG 服务栈

```powershell
Set-Location D:\A-xk-project\Buffeed（请改为自己的目录）
powershell -ExecutionPolicy Bypass -File .\deploy\compose.ps1 up -d docling-serve lightrag gateway rag-worker
powershell -ExecutionPolicy Bypass -File .\deploy\compose.ps1 logs -f gateway lightrag rag-worker docling-serve
```

### 终端三：Electron desktop

```powershell
Set-Location D:\A-xk-project\Buffeed（请改为自己的目录）
# Compose 场景导入文件时，宿主机目录和容器目录必须显式对应
$env:RAG_INGEST_MODE = "container"
$env:RAG_INGEST_HOST_DIR = (Resolve-Path .\data/rag\inputs).Path
$env:RAG_INGEST_GATEWAY_DIR = "/srv/rag/ingest"
powershell -ExecutionPolicy Bypass -File .\apps\desktop\run.ps1 -Mode dev
```

若只想调试 Agent，不启动 RAG，可省略终端二，并在终端三不设置 `RAG_INGEST_MODE=container`。desktop 检测到终端一已健康时不会重复启动 Agent API。

Agent Workspace HUD 的文件统计由 Agent API facade 提供：`GET /api/v1/sessions/{session_id}/changes`；统计按回合账本对路径去重并累计新建、删除、修改过程中的行差异，因此新建后删除的文件仍会显示为一个 `+N -N` 文件记录。审核和撤销分别使用 `POST .../changes:review` 与 `POST .../changes:revert`。撤销只作用于会话开始时未 dirty 的路径，会保护用户原有工作树修改。

### 可选：仅调试 RAG REST/MCP facade

```powershell
Set-Location D:\A-xk-project\Buffeed（后续改为自己的目录）
uv run --project apps/rag python apps/rag/run.py
```

实现模块来自 `apps/rag`，默认 `RAG_DATA_ROOT` 仍指向 `data/rag`，因此相对输入、artifact 和本地状态保持不变。需要完全独立的数据根时显式设置 `RAG_DATA_ROOT` 和 `RAG_RUNTIME_CWD`。

Agent runtime 自带 `apps/agent-runtime/skills` 和 `.mcp.json` 默认资源；工作区根下的同名 `skills/` 与 `.mcp.json` 优先覆盖 bundled 默认值，机器级配置仍可通过 `MCP_CONFIG_PATH` 显式指定。

## 健康检查

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health
Invoke-RestMethod http://127.0.0.1:8001/api/v1/rag/health
Invoke-RestMethod http://127.0.0.1:8001/api/v1/rag/ready
```

这些命令只说明检查方式，不代表当前环境已经启动服务。健康检查中的 `team_tools_enabled` 反映当前回合能力；旧回合成员即使仍出现在历史画布中，也不会继续运行。Electron 直接连接主机 RAG 时使用 `RAG_INGEST_MODE=host`（默认 auto 也按 host 处理）；Compose 场景请显式设置 `RAG_INGEST_MODE=container`，网关路径默认为 `/srv/rag/ingest`。遇到 `MODEL_ID`、Docker、数据库或模型端点错误时，应先修复对应边界，不要通过改变 UI 路径绕过。

## 停止服务

```powershell
Set-Location D:\A-xk-project\Buffeed（后续改为自己的目录）
powershell -ExecutionPolicy Bypass -File .\deploy\compose.ps1 down
```

Compose 配置检查不等于容器已运行；健康检查返回成功后，再进入桌面功能调试。`apps/desktop` 的 `tsc/build` 需要先完成本目录的 `npm ci`。

可选的 howtocook MCP 示例不会被默认加载。需要启用时，设置 `MCP_CONFIG_PATH` 指向你自己的 JSON 配置，并确认其中的 `command`、`args` 和 `cwd` 是当前机器上的有效路径。
